# UBA Backend API Contract

This document organizes the UBA external/internal API contracts based on the actual Protobuf definitions (`backend/api/protos/`), serving as the authoritative reference for secondary development and SDK integration.

> Interface contract first: all APIs are defined in `.proto` files, with Go / TypeScript / OpenAPI code generated via buf. See [Code Generation Pipeline](./tutorial-codegen.md) for details.

---

## 1. Proto Layering


## 2. Report Service (Collector)

### `ReportService` (`uba/service/v1/report.proto`)

| RPC | Description |
|-----|------|
| `PostReport(PostReportRequest) returns (PostReportResponse)` | Unified reporting interface, supports mixed reporting of behavior/risk events |

### HTTP Endpoint

- `POST /uba/v1/report`

### Authentication

- `appId` + `appSecret` are placed in the **request body** (not headers); no Authorization token.
- Authentication failure returns `401`; the SDK **does not retry**.

### Request Body Structure (camelCase, protojson encoding)

```jsonc
{
  "appId": "your_app_id",
  "appSecret": "your_app_secret",
  "clientInfo": { "userAgent": "...", "referer": "..." },
  "events": [
    {
      "eventType": "BEHAVIOR",        // BEHAVIOR | RISK
      "eventId": "uuid",              // auto-generated by the SDK, unique
      "eventName": "click",           // required
      "eventTime": "RFC3339",         // auto-completed by the SDK
      "deviceId": "...",              // persisted by the SDK, stable per device
      "sessionId": "...",             // session level
      "platform": "web",              // detected by the SDK
      "userId": 1001,                 // carried automatically after identify
      "properties": { "button": "buy" },
      "behavior": { "objectType": "button", "objectId": "btn_buy" }
    }
  ]
}
```

> `tenantId` is **not reported**; the server authoritatively identifies and overrides it based on appId, ensuring multi-tenant isolation.

### Event Types (oneof payload of the events element)

| Type | Fields | Triggering API |
|------|------|---------|
| Behavior event (`BEHAVIOR`) | `behavior` + `properties` | SDK `track` / `trackBehavior` |
| Risk event (`RISK`) | `risk` (riskType / riskLevel / riskScore / description) | SDK `trackRisk` |

### Response Conventions

- HTTP `200` may still contain **partial failures**: when the response body has `failedCount > 0` or a non-empty `errorsByType`, the SDK logs a warning.
- Error codes: `400` validation failure, `401` authentication failure (no retry), `500` server error (retry).
- Error bodies follow the Kratos error envelope format.

## 3. Analytics Aggregation Service

### `AnalyticsService` (`uba/service/v1/analytics.proto`)

A total of **25** analysis model RPCs (grouped by scenario, corresponding to lines 11-83 of the proto):

| Scenario | RPC | Purpose |
|------|-----|------|
| **Basic aggregations** | `EventTrend` | Event volume trend (time bucketing) |
| | `GroupBy` | Dimension group aggregation (whitelisted dimensions + metrics) |
| | `ActiveUsers` | DAU / WAU / MAU (daily-level true values via HLL rolling windows) |
| **Conversion & paths** | `Funnel` | Funnel analysis (multi-step conversion) |
| | `Retention` | Cohort retention matrix |
| | `PathSankey` | Top conversion paths (Sankey diagram) |
| | `BehaviorSequence` | Behavior sequence analysis |
| **In-depth user insights** | `Attribution` | Attribution analysis (first-touch/last-touch) |
| | `Distribution` | Distribution analysis (duration bucketing + percentiles) |
| | `Segmentation` | User segmentation / targeting |
| | `Click` | Click heatmaps |
| | `Interval` | Interval time analysis |
| **Lifecycle** | `Lifecycle` | User lifecycle |
| | `Churn` | Churn and win-back analysis |
| | `NewVsOld` | New vs. returning user comparison |
| | `Matrix` | Matrix / quadrant analysis |
| **Revenue & value** | `Revenue` | Revenue analysis (ARPU/ARPPU/GMV) |
| | `WhaleTier` | Paying-user tiers (whale users) |
| | `LTV` | Historical lifetime value |
| **Sessions & anomalies** | `SessionAnalysis` | Session analysis (bounce rate/depth/percentiles) |
| | `Anomaly` | Year-over-year / month-over-month, anomaly detection |
| **Game-specific** | `LevelAnalysis` | Level / numeric balance analysis |
| | `ServerRetention` | Merged-server retention (by server) |
| | `OnlineStats` | Concurrent online PCU / ACU |
| | `Economy` | Economy system / token flows |

### Common Messages

- `AnalyticsGranularity` enum: `UNSPECIFIED=0`, `HOUR=1`, `DAY=2`, `WEEK=3`, `MONTH=4`.
- `TimeRange`: `start_ms` (inclusive), `end_ms` (inclusive), Unix milliseconds. When omitted, the default is end = now and start = 7 days ago.
- `TimeSeriesPoint`: `timestamp` (ms), `value` (double).

### Request Essentials

The request messages (`*Request`) of the 25 models follow unified conventions:

- **Common fields**: `time_range` (`TimeRange`), optional `app_id` (used in the repository as a `tenant_id` isolation predicate; `0`/absent means all tenants). Time-series models also carry `granularity` (`AnalyticsGranularity`).
- **Filter fields**: `event_name` / `platform` / `dimension` etc. are carried according to each model's semantics. `GroupBy`'s `dimension` uses a **whitelist**: `platform/channel/country/app_version/event_name/event_category/os/network` (game models additionally support `server_id`/`level` etc.).
- **Model-specific parameters**: e.g. `FunnelRequest.steps` (`repeated string`, **≥2**), `RetentionRequest.retention_type` (`ACTIVE`/`EVENT`) + `max_offset_days`, `GroupByRequest.metric` (`COUNT`/`UNIQUE_USER`/`SUM_AMOUNT`), etc.

> For the complete field-by-field definitions of the 25 models, consult `backend/api/protos/uba/service/v1/analytics.proto` (request/response messages with full field comments), or the Swagger docs generated by running `make openapi`.

## 4. Behavior Event Service

### `BehaviorEventService` (`uba/service/v1/behavior_event.proto`)

| RPC | Description |
|-----|------|
| `Create(BehaviorEvent) returns (Empty)` | Insert a single event |
| `BatchCreate(BatchCreateBehaviorEventRequest) returns (Empty)` | Batch insert |
| `List(PagingRequest) returns (ListBehaviorEventResponse)` | Paginated query |
| `Get(GetBehaviorEventRequest) returns (BehaviorEvent)` | Query a single event |

### Full Set of `BehaviorEvent` Fields (corresponds to `events_fact`)

| Field | Type | Group |
|------|------|------|
| `event_id`, `tenant_id` | string / uint32 | Routing/identity |
| `user_id`, `device_id`, `account_id`, `global_user_id` | uint32 / string | Subject (Who) |
| `event_time`, `event_ts`, `server_time` | Timestamp / int64 | Time |
| `event_category`, `event_name`, `event_action` | string | Behavior (What) |
| `object_type`, `object_id`, `object_name` | string | Object |
| `session_id`, `session_seq` | string / uint32 | Session context |
| `platform`, `os`, `app_version`, `channel` | string | Environment |
| `ip`, `ip_city`, `country`, `network`, `geo`, `user_agent`, `referer` | string | Network/location |
| `context` | map\<string,string\> | Business context |
| `duration_ms`, `amount`, `quantity`, `score`, `metrics` | uint32/string/int32/map | Metrics |
| `properties` | map\<string,string\> | Extended properties |
| `op_result`, `error_code`, `risk_level`, `trace_id` | string | Enterprise/operations |
| `click_x`, `click_y`, `element_xpath`, `page_url`, `viewport_width` | uint32 / string | Heatmap (filled by autotrack) |
| `server_id`, `level` | string / uint32 | **Game-specific dimensions** (server ID / player level) |
| `created_at`, `updated_at` | Timestamp | Timestamps |
