# 风行看板

风行看板是一款实时协作看板系统，以「看板 + 列 + 卡片」的方式组织团队任务与现场作业。
系统采用**微服务 / 单体自由切换**的架构设计，通过 **SSE / WebSocket** 实现多端实时同步；
移动端基于 Flutter **一套代码六端编译**（iOS / Android / Web / macOS / Windows / Linux），
面向一线与现场作业场景优化，支持**离线优先**。

如果你正在寻找 Focalboard（Mattermost Boards）的替代选择，风行看板值得一试。
项目采用 **MIT 协议**开源，欢迎试用、反馈与共建。

::: tip 项目快速迭代中

## 一、核心亮点

### 1. 看板管理

- **看板 / 列 / 卡片**：看板、列、卡片的创建与编辑一应俱全；
- **拖拽流转**：卡片跨列拖拽即完成状态流转，上手零成本。

### 2. 标签管理

- **标签体系**：以标签标注卡片的类型、优先级或归属；
- **灵活组织**：同一看板内按标签归类与筛选任务，聚焦重点。

### 3. 跨端实时同步

- **SSE / WebSocket 双通道**：卡片的新增、移动、编辑实时广播给所有协作者；
- **多端一致**：Web 后台与移动 App 看到的看板状态始终一致，协作不互相覆盖。

### 4. 离线优先

- **弱网可用**：面向一线与现场作业优化，网络不稳定时仍可继续操作；
- **现场友好**：断网照常采集，恢复联网后自动同步，贴合车间、工地、外勤等场景。

### 5. 多租户与权限

- **多租户隔离**：多团队、多业务共用一套部署，数据相互隔离；
- **RBAC 权限**：权限控制细化到菜单级、按钮级、数据级。

### 6. 平台基座能力

- **开箱即用的基座**：内置字典管理、任务调度、登录策略、多语言、站内信；
- **五类审计日志**：关键操作全量留痕，满足运维排查与合规需要。

## 四、适用场景

### 一线与现场作业

为车间、工地、门店、外勤等一线场景设计：

- 离线优先，弱网、断网环境下照常看板作业；
- Flutter 一套代码覆盖手机、桌面与 Web，现场设备即装即用；
- 恢复联网后数据自动同步，后台实时掌握现场进展。

### 团队任务协作

以看板驱动的小团队任务管理：

- 卡片拖拽流转状态，标签标注优先级与归属；
- SSE / WebSocket 实时同步，成员之间协作无延迟。

### Focalboard 替代与自托管

替换停维的 Focalboard（Mattermost Boards）：

- MIT 开源、可自托管，数据完全自主可控；
- 微服务 / 单体自由切换，从个人部署到企业集群平滑伸缩。

### 多团队共用一套部署

多租户架构支撑多业务线并行：

- 多团队、多业务数据相互隔离；
- 菜单级、按钮级、数据级的 RBAC 权限按需分配。

## 五、技术栈与部署

后端基于 go-kratos 框架构建，数据访问层采用 Ent ORM，业务数据由 PostgreSQL 存储，
支持微服务与单体两种形态自由切换；
管理后台基于 Vue3、Ant Design Vue 与 Vben Admin 构建，移动端使用 Flutter 开发，
一套代码编译 iOS / Android / Web / macOS / Windows / Linux 六端。

| 组件 | 说明 |
| --- | --- |
| 后端 | go-kratos + Ent + PostgreSQL，微服务 / 单体自由切换 |
| 管理后台 | Vue3 + Ant Design Vue + Vben Admin |
| 移动端 | Flutter，一套代码六端编译 |
| 实时通道 | SSE / WebSocket |
| 部署 | docker-compose 支持 `full_deploy`（中间件 + 应用一键部署）与 `libs_only`（仅中间件，推荐开发调试）两种模式 |
